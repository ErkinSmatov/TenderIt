Deliver the application-creation vertical slice: extend `GoszakupPortalClient` with portal steps 1-11
(create_application, add_lots, lots_next, beneficiary save_info, docs_next, get_encr_info, add_encrypt,

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → /api/goszakup/* | Untrusted step payloads (encryptedData, signData) cross to backend proxy |
| backend proxy → goszakup portal | Server-side form-encoded POSTs using the stored session |
| browser → NCALayer (localhost) | Gamma encrypt + GOST sign on device |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-20 | Information Disclosure | /api/goszakup/* session use | mitigate | Session loaded per-user from Redis by user_id from JWT; a user can only drive their own session |
| T-05-21 | Spoofing | direct browser→goszakup XHR | mitigate | All portal calls routed through backend proxy; no cross-origin XHR (CORS pitfall) — verified by grep gate |
| T-05-22 | Tampering | stale CSRF token | mitigate | Refresh + re-store CSRF from each portal response; 403 triggers re-login flow |
| T-05-23 | Information Disclosure | encryptedData/signData logging | mitigate | Proxy does not log encrypted blobs or session secrets |
</threat_model>
