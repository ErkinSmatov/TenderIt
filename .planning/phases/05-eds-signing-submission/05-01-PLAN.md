<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → /api/applications | Untrusted JSON body (tender_id, lots_data, document_ids) crosses here |
| backend → goszakup portal | Server-side form-encoded POST with stored session |
| Redis ↔ backend | Session secrets (PHPSESSID, CSRF) at rest with TTL |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-01 | Information Disclosure | GET /api/applications/{id} | mitigate | get_user_application filters `WHERE id AND user_id`; returns 404 not 403 (IDOR, mirrors Phase 4) |
| T-05-02 | Tampering | POST /api/applications user_id | mitigate | user_id always from JWT `current_user.id`, never from request body |
| T-05-03 | Information Disclosure | goszakup_portal_client logs | mitigate | Never log or print phpsessid / csrf; audit only the event, not secret values |
| T-05-05 | Input Validation | ApplicationCreate.lots_data | mitigate | Pydantic schema validates types + non-empty lots_data at route entry |
| T-05-06 | Elevation of Privilege | Redis goszakup_session TTL | mitigate | Hard TTL 72000s (20h) on every write; no unbounded session persistence |
</threat_model>
