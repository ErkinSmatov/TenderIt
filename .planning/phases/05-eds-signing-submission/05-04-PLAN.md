<objective>
Build the durable auto-submission engine: add python-telegram-bot, an ARQ worker (`WorkerSettings` +
`poll_watchlist_tenders` cron every 5 min + `auto_submit_application` job), the Telegram send helper and
FastAPI `/api/telegram/webhook` confirm handler, and the 15-minute Redis confirm/fallback logic. When a
watched tender opens (status_id 220), the worker notifies the user with Да/Нет buttons, enqueues a
deduplicated 15-min fallback submit, and finalizes via `public_application` with retry/backoff to ~30 min.

Purpose: This is the "auto-submit the moment the tender opens" promise — the product's core value. It runs
as a separate ARQ process and reuses the 05-01 session + state machine (never modifying those services).

Output: dependency + settings + worker package + telegram service + webhook router + main.py registration + tests.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Telegram servers → /api/telegram/webhook | Untrusted inbound updates (callback_data) |
| ARQ worker → goszakup portal | Automated submit using stored session |
| Redis ↔ worker/webhook | confirm + session state |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-30 | Tampering | callback_data app_id (IDOR) | mitigate | Verify the callback chat_id matches the application's user.telegram_chat_id before acting |
| T-05-31 | Spoofing | inbound webhook source | mitigate | Require X-Telegram-Bot-Api-Secret-Token == settings.telegram_webhook_secret; 403 otherwise |
| T-05-32 | Tampering | duplicate/replay submit | mitigate | Stable `_job_id=f"submit:{app_id}"` dedups fallback + triggered jobs; check status before submit |
| T-05-33 | Information Disclosure | session secrets in worker logs | mitigate | Never log phpsessid/csrf; audit event only |
| T-05-34 | Denial of Service | infinite submit retries | mitigate | BACKOFF_SECONDS capped at 7 tries (~30 min) then mark_error final |
</threat_model>
