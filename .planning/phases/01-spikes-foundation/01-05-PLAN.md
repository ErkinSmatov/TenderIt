    ## Context for Attorney
    Describe TenderIt in non-technical terms for a Kazakhstan-licensed attorney:
    - TenderIt is a software service that helps Kazakhstani companies submit tender applications to goszakup.gov.kz programmatically
    - The submission flow: (1) the software assembles the application document, (2) the company director personally clicks "Sign" on their screen and enters their NCALayer PIN — this is a physical, contemporaneous act by the authorized representative, (3) NCALayer signs the document on the director's device, (4) the software transmits the signed document to goszakup via the official API
    - The private signing key never leaves the director's device
    - The company director is physically present and actively consents to each submission (not a scheduled/automated submission without the director's knowledge)

    ## Legal Questions for Attorney Consultation

    Question 1 — Automated Submission Permissibility:
    Does using software to programmatically call goszakup.gov.kz API (with the company director's per-action consent via NCALayer PIN entry) constitute permissible use under:
    - goszakup.gov.kz Terms of Service (specifically: does the ToS prohibit programmatic API access?)
    - Kazakhstan Law on Public Procurement (Закон РК No. 434-V)
    - Any applicable regulations from Министерство финансов РК or Агентство по защите и развитию конкуренции?

    Question 2 — EDS Authorization under ЗЭЦД:
    Under the Law on Electronic Documents and Digital Signatures (Закон РК No. 370-II "Об электронном документе и электронной цифровой подписи"):
    - Does per-action user consent (director clicks "Sign" button + enters NCALayer PIN) satisfy the authorization requirement for each submitted tender document?
    - Is there a requirement that the authorized person must be the one to initiate the signing session (vs. having software initiate it while the person confirms)?
    - Are there specific certificate type requirements (AUTH vs SIGNATURE vs GOST) for tender submission?

    Question 3 — Liability Framework:
    - What is the liability allocation if TenderIt software submits an erroneous bid (incorrect price, wrong documents) even though the director clicked "Sign"?
    - Is there a disclosure requirement to goszakup when using third-party software to submit applications?

    Question 4 — Data Localization:
    Under the Law on Personal Data (Закон РК No. 94-VI, amended 2023, effective 8 January 2025):
    - Which user data categories collected by TenderIt require Kazakhstan-based storage: BIN (business identification number), IIN (individual identification number), director's full name, company legal address, uploaded company documents (ГКП, лицензии, etc.), tender application contents?
    - What constitutes "processing" for the purpose of the localization requirement — does viewing and transmitting data to goszakup constitute processing requiring KZ storage?
    - Is hosting on AWS Frankfurt with a KZ subdomain compliant, or must physical servers be in Kazakhstan?
    - What are the penalties for non-compliance?

    Question 5 — goszakup Partner Agreement:
    - Is there a formal partner program or API usage agreement that TenderIt must sign with АО "ЦЭФ" (Центр Электронных Финансов) before providing the service commercially?
    - Is the API token (obtained via letter) sufficient for commercial use, or is a separate commercial license required?

    Option B — Playwright browser automation: Render MP.kz pages in a headless browser, extract data from the DOM. This is resilient to API changes but slower and more fragile to UI changes.

    ## Consequences

    ### Option A (Internal API) — if selected:
    Positive:
    - Fast sync (< 1s per request vs 5-15s for Playwright)
    - No Playwright Docker dependency
    - Predictable rate limiting behavior

    Negative/Risks:
    - MP.kz internal API may change without notice (no versioning SLA)
    - May require session authentication (user session cookie)
    - May require login credentials which changes the data model (storing MP.kz credentials)

    ### Option B (Playwright) — if selected:
    Positive:

    - Mimics real browser behavior (harder to block)

    - Playwright adds ~500MB Docker image weight
    - Scraping is 5-10x slower than API calls
    - Fragile to UI changes (requires maintenance on every MP.kz redesign)
    - ARM64 Mac + Playwright has known Docker compatibility issues

  <name>SPIKE-04: Execute MP.kz network traffic analysis</name>
  <what-built>
    This is a manual browser investigation of MP.kz (mp.kz) network traffic. No account is required — tender listings are publicly visible.
  </what-built>
  <how-to-verify>
    Step 1 — Open Chrome DevTools on mp.kz:
      Open https://mp.kz in Google Chrome.
      Open DevTools (F12), go to Network tab.
      Check "Preserve log". Filter by "Fetch/XHR".

    Step 2 — Browse tender listings:
      Navigate to the tender listings page (typically under /tenders or /zakupki or similar).
      Scroll down to trigger pagination or lazy loading.
      Watch the Network tab for XHR/Fetch requests.

    Step 3 — Analyze each observed request:
      For each Fetch/XHR request, record:
      - Full URL (method + host + path + query parameters)
      - Request headers (especially Authorization, Cookie, Content-Type)
      - Response Content-Type (application/json → internal API candidate)
      - Response structure (first 200 chars of response body)
      - Whether the request requires authentication (check: does it work if you clear cookies and reload?)

    Step 4 — Check for GraphQL:
      Look for requests to /graphql or with {"query": "..."} in the request body.
      Check request payloads for GraphQL query syntax.

    Step 5 — Check for pagination API:
      Find how tender list pagination works: URL query params (?page=2&limit=20) or POST body?
      Record the exact pagination mechanism.

    Step 6 — Test without login:
      Open a private/incognito window. Visit mp.kz tender listings.
      Check: do the same API calls work without a session cookie?
      Record which endpoints require authentication.

    Step 7 — Save findings:
      Right-click any JSON API response → "Open in new tab" → save the JSON
      Save as: backend/spikes/findings/mpkz-api-sample-response.json (if JSON API found)

    Key question: Is the response from tender listing calls application/json (→ internal API) or text/html (→ server-rendered, must scrape)?

    After recording findings, also check mp.kz for any developer/API documentation links (footer, /api-docs, /developers).
