<objective>
Capture the exact HTTP requests made during a real manual tender application submission on goszakup.gov.kz by intercepting browser network traffic.

Purpose: The Phase 5 submission service (APPL-03) assembles the application XML payload and calls the goszakup submission endpoint. Without knowing the exact payload structure — every mandatory field, the signed XML wrapper format, and the endpoint URL — the implementation is building against guesswork. This spike provides the ground truth that makes Phase 5 deterministic.

Output: Captured and anonymized submission payload files (JSON + XML), and SPIKE-03-FINDINGS.md with a complete field registry that the Phase 5 XML assembly template will be built against.
</objective>

<task type="checkpoint:human-action" id="1" gate="blocking">
  <name>SPIKE-03: Capture goszakup submission payload via browser DevTools</name>
  <what-built>
    This is a manual browser investigation. No code is written in this task.
    A real goszakup supplier account and access to an active tender (ideally a low-value test tender or one already submitted before) are required.

    SAFETY NOTE: If you have access to a test tender (small amount, your company pre-approved as a supplier), proceed. If you are unsure whether submitting constitutes a binding legal obligation in your jurisdiction, consult a lawyer before proceeding. Alternatively, capture up to the final confirmation step and stop — the payload is visible in DevTools before the final submission click.
  </what-built>
  <how-to-verify>
    Setup:

    1. Open Google Chrome on the machine with a goszakup supplier account.
    2. Open DevTools (F12 or Cmd+Option+I).
    3. Go to the Network tab.
    4. Check "Preserve log" checkbox.
    5. Check "Disable cache" checkbox.
    6. In the filter bar, select "Fetch/XHR" to show only API calls.
    7. If using mitmproxy for HTTPS capture (optional, more complete):
         pip install mitmproxy
         mitmweb --listen-port 8080
         Set Chrome proxy to localhost:8080 in System Preferences → Network → Proxies.
         Visit http://mitm.it in Chrome and install the mitmproxy CA certificate.

    Capture process:

    8. Navigate to https://goszakup.gov.kz and log in with your supplier account.
    9. Find an active tender you are eligible to apply for (or use a previously submitted one to observe the re-application flow).
    10. Begin the application process. Do NOT submit unless you are certain it is a test scenario.
    11. Fill in all required application fields step by step. Watch the Network tab for API calls at each step.
    12. At the signing step, when the system would normally call NCALayer — STOP if you cannot sign safely. The payload to the signing endpoint is what we need, not the final signed submission.
    13. If you can complete the full submission safely: proceed through signing and submission. Record all API calls.

    What to capture:

    For EACH API call observed during the application flow:
    - Right-click → "Copy as cURL" → paste into a text file
    - OR: Click the request → Headers tab → copy all headers → Payload tab → copy request body

    Priority captures (most critical):
    A. The call that creates the application draft (first POST to an /applications or /trdapp endpoint)
    B. The call that retrieves the unsigned XML to sign (GET or POST that returns payloadXml)
    C. The call that submits the signed XML (POST with the CMS/XMLDSig signed document)
    D. Any calls that attach documents to the application

    Save the raw captures to: backend/spikes/findings/raw-captures/ (create this directory)

    After capture, export a HAR file:
    - DevTools → Network tab → click the down-arrow export button → "Export HAR..."
    - Save as: backend/spikes/findings/goszakup-submission-session.har
    - NOTE: HAR files may contain your session cookies. Redact Authorization headers and Cookie values before committing to git.
  </how-to-verify>
  <resume-signal>Type "spike-03 captured" with a brief summary: (1) whether you reached the signed submission step, (2) how many distinct API calls you observed during the flow, (3) the host domain of the submission endpoint (e.g., goszakup.gov.kz, v3bl.goszakup.gov.kz, ows.goszakup.gov.kz)</resume-signal>
