<objective>
Verify NCALayer WebSocket protocol against a real NCALayer installation with a real ЭЦП certificate: confirm the actual listening port, document the exact JSON-RPC message envelopes for getKeyInfo and signXml, test signing a real XML payload, and identify which certificate type is valid for tender document signing.

Community sources conflict on port (13579 vs 14579) and the official SDK requires pki.gov.kz registration to access. This spike produces the byte-exact specification the useNCALayer() React hook will be built against.

Output: Standalone HTML test harness that runs in any browser on the NCALayer machine, executed against live NCALayer, recorded JSON message logs, and SPIKE-02-FINDINGS.md with confirmed protocol specification.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser → NCALayer localhost | WebSocket to 127.0.0.1; NCALayer handles PIN entry and private key access |
| Test XML → NCALayer → signed XML | NCALayer signs with the real private key; signed output contains a real signature |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | Information Disclosure | Real ЭЦП certificate PIN entered during spike | mitigate | Use a test/development certificate for the spike, not the company's production signing key if possible; the PIN is entered in NCALayer's own dialog, not in the test HTML page |
| T-03-02 | Information Disclosure | Signed XML output captured in session log | mitigate | Redact or replace the actual signed XML blob in any public findings document; the structure documentation is what matters, not the actual signature over real company data |
| T-03-03 | Tampering | ncalayer-test.html served from untrusted location | accept | The file is opened locally as file:// and used only for investigation; it is not deployed anywhere |
| T-03-04 | Elevation of Privilege | Accidental production tender submission during spike | mitigate | The spike uses a minimal test XML (<tender><id>TEST-001</id>...</tender>); this is not a valid submission payload and will not constitute a binding legal action even if signed |
</threat_model>
