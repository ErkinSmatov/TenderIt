<objective>
First vertical slice. Delivers AUTH-01 (registration) and the login half of AUTH-02:
- POST /api/auth/register hashes password with pwdlib Argon2, persists User, returns 201 + sets both cookies
- POST /api/auth/login verifies password, issues access (15 min) + refresh (7 d) tokens as httpOnly cookies, stores refresh token in Redis
- Both endpoints rate-limited via slowapi (5/min per IP)
- Frontend has /register and /login pages (RHF + zod), shared api client with credentials: include, Zustand auth store
- middleware.ts protects /dashboard via jose JWT verification
- /dashboard placeholder page renders so the protected route round-trip is observable

Purpose: After this plan, a real user can register, log in, and reach a protected page —
the core auth vertical end-to-end. Refresh/logout/reset arrive in subsequent waves.
Output: Backend auth router + schemas + services + deps; Next.js middleware + api client + auth store + two auth pages + dashboard placeholder; integration tests for register and login.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → FastAPI | Untrusted client input; all bodies validated via Pydantic v2; rate limited per IP |
| browser → middleware (Edge) | Cookie attacker-controllable; signature verification via jose with shared HS256 secret |
| FastAPI → Redis | Trusted internal network; refresh token round-trip |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-02-01 | Spoofing | POST /api/auth/login brute force | mitigate | slowapi @limiter.limit("5/minute") per IP via get_remote_address; same error message for unknown email and wrong password (no user enumeration) |
| T-02-02-02 | Spoofing | POST /api/auth/register account spam | mitigate | slowapi @limiter.limit("5/minute") per IP (Pitfall 7); pydantic EmailStr + min_length(8) prevents trivial inputs |
| T-02-02-03 | Tampering | JWT algorithm confusion | mitigate | jwt.decode(..., algorithms=["HS256"]) explicit on every decode site (deps.py get_current_user); jose middleware similarly uses HS256 via TextEncoder secret |
| T-02-02-04 | Information Disclosure | XSS-stolen JWT | mitigate | Both cookies set with httpOnly=True; no JWT stored in localStorage or accessible to document.cookie |
| T-02-02-05 | Tampering | CSRF on /api/auth/login | mitigate | samesite="lax" blocks cross-site POST cookies (CSRF prerequisite); CORS only allows settings.frontend_url with credentials |
| T-02-02-06 | Information Disclosure | Email enumeration via timing | mitigate | Same error string for unknown email vs wrong password; pwdlib verify is timing-safe; consider always running verify even when user missing — add dummy hash compare in login handler to equalise timing |
| T-02-02-07 | Information Disclosure | JWT_SECRET committed to repo | mitigate | settings.jwt_secret reads from JWT_SECRET env var; .env in .gitignore; .env.example contains placeholder + generation hint |
| T-02-02-08 | Elevation of Privilege | Weak password accepted | mitigate | min_length=8 (Argon2 default for MVP); future hardening (zxcvbn) flagged as v2; argon2 cost factor uses pwdlib default which is ≥ Argon2id m=64MB, t=3, p=4 |
| T-02-02-09 | Denial of Service | Argon2 CPU exhaustion via rapid registrations | accept | Argon2 is intentionally expensive; rate limit + slowapi 5/min upper-bounds attacker spend; document tradeoff |
</threat_model>
