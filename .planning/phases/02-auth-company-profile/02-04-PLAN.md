<objective>
Third wave. Delivers AUTH-03 (password reset by email).

- POST /api/auth/forgot-password {email}: generates opaque 32-byte URL-safe token,
  stores reset:{token} -> user_id in Redis with 900s TTL, sends email via Resend
  (or logs link in debug). Returns 202 regardless of whether email exists (no enumeration).
- POST /api/auth/reset-password {token, new_password}: atomically consume reset token
  via redis.getdel, look up user, update hashed_password, return 204. Reuse fails with 400.
- Frontend pages: /forgot-password (email input) and /reset-password (reads ?token= from URL, password input).

Purpose: Closes the AUTH-03 requirement and the Pattern-5 / Pitfall-7 surface area.
Output: Email service, two new endpoints, two new frontend pages, 6+ integration tests.
</objective>

    @router.post("/forgot-password", status_code=202)
    @limiter.limit("3/minute")
    async def forgot_password(request: Request, body: ForgotPasswordRequest, db = Depends(get_db), redis = Depends(get_redis)):
      result = await db.execute(select(User).where(User.email == body.email))
      user = result.scalar_one_or_none()
      if user:
        token = await create_reset_token(redis, user.id)
        link = f"{settings.frontend_url}/reset-password?token={token}"
        await send_password_reset_email(user.email, link)
      return {"message": "Если email зарегистрирован, ссылка отправлена"}

    @router.post("/reset-password", status_code=204)
    @limiter.limit("5/minute")
    async def reset_password(request: Request, body: ResetPasswordRequest, db = Depends(get_db), redis = Depends(get_redis)):
      user_id = await consume_reset_token(redis, body.token)
      if user_id is None:
        raise HTTPException(status_code=400, detail="Ссылка недействительна или истекла")
      user = await db.get(User, user_id)
      if user is None:
        raise HTTPException(status_code=400, detail="Ссылка недействительна или истекла")
      user.hashed_password = hash_password(body.new_password)
      await db.commit()
      return Response(status_code=204)

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → /api/auth/forgot-password | Unauthenticated; email is attacker-controlled |
| email link → /api/auth/reset-password | Token is the only authentication factor; must be single-use and short-lived |
| FastAPI → Resend API | Outbound TLS; API key in env only |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-04-01 | Spoofing | Token reuse / replay | mitigate | redis.getdel is atomic — first consumer wins, second sees None; covered by replay test |
| T-02-04-02 | Information Disclosure | Email enumeration via forgot-password | mitigate | Identical 202 response and timing for known and unknown email; Resend send is non-blocking (try/except swallow) so timing does not leak existence |
| T-02-04-03 | Tampering | Predictable reset token | mitigate | secrets.token_urlsafe(32) — 256 bits of entropy from os.urandom; not a JWT (no signature to attack) |
| T-02-04-04 | Denial of Service | Reset email flood | mitigate | @limiter.limit("3/minute") on /forgot-password per IP; Resend free tier 3000/month is upper-bounded by rate limit math |
| T-02-04-05 | Information Disclosure | Reset token logged | mitigate | In debug mode, link is printed to stdout (acceptable for dev); in prod, token never logged — only embedded in outbound email body |
| T-02-04-06 | Elevation of Privilege | Long-lived reset token | mitigate | 900s TTL (A1) — Redis auto-expires |
| T-02-04-07 | Tampering | Token smuggled via referer / browser history | accept | Token is URL query param; standard for reset flows; single-use + 15-min TTL bound exposure window |
| T-02-04-08 | Spoofing | Brute force token guessing | mitigate | 32-byte URL-safe = ~190 bits; @limiter.limit("5/minute") on /reset-password caps attempts; combined with 900s TTL infeasible to guess |
</threat_model>
