<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → /api/tenders, /api/watchlist | Auth-gated; user_id derived from JWT, never from request |
| FastAPI → Postgres | Parameterised queries; user-scoped filters on watchlist |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-02-01 | Elevation of Privilege | IDOR: user removes/lists another user's watchlist entry | mitigate | DELETE and GET /watchlist filter by current_user.id (from JWT); DELETE keyed on (user_id, number_anno) never on watchlist id |
| T-03-02-02 | Spoofing | user_id supplied in request body to act as another user | mitigate | user_id always current_user.id; WatchlistAddRequest contains only number_anno |
| T-03-02-03 | Denial of Service | Unbounded number_anno length | mitigate | WatchlistAddRequest max_length=100; path param stripped |
| T-03-02-04 | Tampering | Stored XSS via raw_data/lots_data rendered downstream | accept | JSONB displayed read-only via React auto-escape in Wave 3; no dangerouslySetInnerHTML (RESEARCH Security Domain) |
| T-03-02-05 | Information Disclosure | Unauthenticated tender lookup | mitigate | All routes Depends(get_current_user); 401 asserted in tests |
</threat_model>
