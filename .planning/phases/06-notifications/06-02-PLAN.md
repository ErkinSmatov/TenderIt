<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser → GET /api/notifications/status | JWT cookie required; polling is client-initiated — no server push |
| Browser → POST /api/notifications/telegram/link-token | JWT cookie required; deep_link URL returned to client |
| Browser → DELETE /api/notifications/telegram | JWT cookie required; no body sent — chat_id derived server-side |
| Browser → DELETE /api/watchlist/{number_anno} | JWT cookie required; IDOR protection in tenders.py (user_id from JWT, not body) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-FE-01 | Information Disclosure | TelegramConnectCard polling | accept | telegram_chat_id is a non-sensitive numeric Telegram ID returned only to the authenticated user; not PII; no mitigation required |
| T-06-FE-02 | Spoofing | deep_link button (external link) | accept | Link opens t.me (Telegram's own domain); rel="noopener noreferrer" on target="_blank" prevents reverse tabnapping; Telegram validates the /start token server-side |
| T-06-FE-03 | Elevation of Privilege | WatchlistSettingsTable DELETE call | mitigate | Frontend calls DELETE /api/watchlist/{number_anno}; IDOR protection already in tenders.py (user_id from get_current_user JWT, never from request body); frontend cannot send another user's number_anno — all entries loaded from GET /api/watchlist which is scoped to current user |
| T-06-FE-04 | Denial of Service | 60-second polling timeout | accept | Polling stops after 60s via setTimeout; QueryClient is not a WebSocket — each 3s refetch is an independent HTTP request; bounded load; no mitigation required |
</threat_model>
